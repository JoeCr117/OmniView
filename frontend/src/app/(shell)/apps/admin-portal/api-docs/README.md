# frontend/src/app/(shell)/apps/admin-portal/api-docs/

## Purpose
An in-app page that surfaces the OmniView API documentation inside the
dashboard shell.

## Role in OmniView
Rendered at `/apps/admin-portal/api-docs`, and the target of the `/api-docs`
legacy redirect. It embeds the backend's django-ninja OpenAPI/Swagger UI so an
admin can explore **every** registered app's endpoints without leaving OmniView.

## Contents
| Item | What it does |
|------|--------------|
| `page.tsx` | Iframes `/api/docs`, passing `?theme=` so Swagger matches the dashboard theme. |

## Conventions & gotchas
- **It lives here, not under ExpenseTracker, because it documents the whole
  API.** `config/api.py` mounts every app's router onto one `NinjaAPI`, so the
  page was never ExpenseTracker-specific — it only happened to be built during
  that app's milestone.
- Being under `apps/admin-portal` makes it **staff-only**: `config/frontend.py`
  404s non-staff on this prefix and `AdminGate` hides it client-side. Note the
  underlying `/api/docs` is gated by `_docs_when_authorized` (a session, not
  staff), so a signed-in non-staff user can still reach Swagger directly.
- The route folder is `api-docs`, not `api`, so the `/api-docs` legacy redirect
  keeps working: `shell/registry.py` derives redirect targets as
  `<app base_path>/<page name>`, so the page name *is* the route segment.
- The iframe needs `X_FRAME_OPTIONS = 'SAMEORIGIN'` (`config/settings/base.py`);
  Django's default `DENY` would blank it.
- The docs themselves are generated by django-ninja (see
  `backend/templates/ninja/`), not authored here.
