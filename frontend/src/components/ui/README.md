# frontend/src/components/ui/

## Purpose
The shadcn/ui primitives — thin, styled wrappers over Radix (and Recharts, for
`chart.tsx`). These are generated by the shadcn CLI and form the visual
vocabulary the rest of the UI is built from.

## Role in OmniView
Everything else (shell chrome, common components, app pages) composes these. They
carry the Tailwind-token styling and dark-mode behaviour, so app code doesn't
restyle buttons/cards/inputs by hand.

## Contents
| Item | What it does |
|------|--------------|
| `button.tsx` `card.tsx` `input.tsx` `label.tsx` `switch.tsx` `separator.tsx` | Core form/layout primitives. |
| `avatar.tsx` `dropdown-menu.tsx` `sheet.tsx` `popover.tsx` | Radix-backed overlays/menus. |
| `command.tsx` | cmdk combobox primitives (no dialog wrapper - see below). |
| `skeleton.tsx` | The loading-placeholder primitive (used by `common/skeletons`). |
| `chart.tsx` | The shadcn Recharts container/tooltip primitives (added via `shadcn add chart`). |

## Conventions & gotchas
- **`popover.tsx` takes a `container` prop and `command.tsx` ships without
  shadcn's `CommandDialog`.** Both for the same reason: Radix portals to
  `document.body`, which is invisible while `#app-viewport` is fullscreened.
  Pass `useOverlayContainer()` to anything that portals, and prefer a
  non-portalled layout where one will do.
- `sheet.tsx` currently has **no importer**. Omni-ERD's inspector was built on
  it and then moved to an in-canvas panel; it is kept because it is a stock
  primitive, not because anything needs it.
- **Generated — edit sparingly.** Prefer composing over modifying, so a future
  `shadcn` regen doesn't clobber changes.
- Style with tokens; dark mode is class-based (next-themes), not media-query.
